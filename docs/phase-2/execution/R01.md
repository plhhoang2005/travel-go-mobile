## 1. Remediation Summary

1. **Profile Privacy (DB-002)**:
   - Dropped insecure policy `Profiles are viewable by everyone`.
   - Created strict authenticated own-row SELECT policy `Users can view own profile` (`id = auth.uid()`).
   - Created authenticated own-row UPDATE policy `Users can update own profile` (`id = auth.uid()`).
   - Anon has NO SELECT or UPDATE privileges on `public.profiles`.
   - Postcondition drift gate verifies that NO unexpected policies exist on `public.profiles`, rejecting unauthorized `ALL`, `SELECT`, `UPDATE`, `INSERT`, or `DELETE` policies, exactly validating the reviewed policy names.
2. **Column-Level Update Protection (DB-004)**:
   - Revoked table-level mutating privileges from `anon`, `authenticated`, and `public`.
   - Explicitly granted `UPDATE (full_name, phone, avatar_url, address)` only to `authenticated`.
   - Protected fields (`role`, `email`, `id`, `created_at`, `updated_at`) cannot be modified by clients.
3. **Hardened Signup Trigger (DB-006)**:
   - Replaced `handle_new_user()` with `SECURITY DEFINER` and `SET search_path = public, pg_temp`.
   - Ignores client-supplied `raw_user_meta_data->>'role'` and unconditionally forces `'customer'`.
   - Verifies existence and `SECURITY DEFINER` attribute of `handle_new_user()` in migration postcondition.
   - Robust fallback handling for OAuth / missing email (assigns default full name and preserves null email).
4. **Least-Privilege Grants & Table RLS (DB-003)**:
   - Revoked `TRUNCATE`, `REFERENCES`, `TRIGGER` across `profiles`, `destinations`, `trips`, `trip_activities`.
   - `destinations`: public SELECT for anon and authenticated; all mutating privileges revoked. Faithfully reconstructed schema: `id text`, `region` check Bắc/Trung/Nam/Tây Nguyên, `weather_cached_temp`, `is_popular`.
   - `trips`: faithfully reconstructed with 11 columns matching SRC-DB-001/002, enterprise schema, and `saved_trip_model.dart` (`destination_name text NOT NULL`, without invented `destination_id` or `actual_cost`).
   - `services`: faithfully reconstructed with `title text`, `service_type` checked for `hotel/flight/bus/tour/combo`.
   - `trip_activities`: authenticated own-row CRUD enforced under RLS; foreign key cascade integrity verified (child exists before deletion, parent deletion affects exactly 1 row, child cascaded).
5. **Harmonized Negative Controls (Source-Written / Intended Behavior)**:
   - NC01: Validates exact policy contract (`Users can view own profile` / `Users can update own profile`). Proves drift gate detects injected permissive `FOR ALL` policy.
   - NC02: Tests real role escalation mutant on `handle_new_user()` with synthetic auth signup and proves exact restoration of reviewed migration trigger.
   - NC03: Proves querying non-existent column produces `UNDEFINED_COLUMN_42703` and is not disguised as authorization denial (`42501`).
