## 1. Remediation Summary

1. **Profile Privacy (DB-002)**:
   - Dropped insecure policy `Profiles are viewable by everyone`.
   - Created strict authenticated own-row SELECT policy (`id = auth.uid()`).
   - Anon has NO SELECT or UPDATE privileges on `public.profiles`.
   - Postcondition drift gate verifies that NO unexpected policies exist on `public.profiles`, rejecting unauthorized `ALL`, `SELECT`, `UPDATE`, `INSERT`, or `DELETE` policies.
2. **Column-Level Update Protection (DB-004)**:
   - Revoked table-level mutating privileges from `anon`, `authenticated`, and `public`.
   - Explicitly granted `UPDATE (full_name, phone, avatar_url, address)` only to `authenticated`.
   - Protected fields (`role`, `email`, `id`, `created_at`, `updated_at`) cannot be modified by clients.
3. **Hardened Signup Trigger (DB-006)**:
   - Replaced `handle_new_user()` with `SECURITY DEFINER` and `SET search_path = public, pg_temp`.
   - Ignores client-supplied `raw_user_meta_data->>'role'` and unconditionally forces `'customer'`.
   - Verifies existence and `SECURITY DEFINER` attribute of `handle_new_user()` in migration postcondition.
   - Robust fallback handling for OAuth / missing email (assigns default full name and preserves null email).
4. **Least-Privilege Grants & Table RLS (DB-003)**:
   - Revoked `TRUNCATE`, `REFERENCES`, `TRIGGER` across `profiles`, `destinations`, `trips`, `trip_activities`.
   - `destinations`: public SELECT for anon and authenticated; all mutating privileges revoked. Audited schema: `id text`, `region` check Bắc/Trung/Nam/Tây Nguyên.
   - `trips` & `trip_activities`: authenticated own-row CRUD enforced under RLS; foreign key cascade integrity verified (child exists before deletion, parent deletion affects exactly 1 row, child cascaded).
   - Audited `trip_activities` schema: uses required `(id, trip_id, day_number, start_time, title, cost, service_id)` matching SRC-DB-001 with foreign key to `services(id)`.
5. **Realistic Negative Controls**:
   - NC01: Permissive `FOR ALL` policy drift caught by real migration gate and clean restoration proved.
   - NC02: Real role escalation mutant on `handle_new_user()` caught by real security assertion helper with actual auth signup and clean restoration proved.
   - NC03: Querying non-existent column produces `UNDEFINED_COLUMN_42703` and is not disguised as authorization denial (`42501`).
   - NC04: Zero-row reparent UPDATE is caught by reparent assertion helper and fails closed.
