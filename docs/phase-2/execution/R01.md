## 1. Remediation Summary

1. **Profile Privacy (DB-002)**:
   - Dropped insecure policy `Profiles are viewable by everyone`.
   - Created strict authenticated own-row SELECT policy `Users can view own profile` (`id = auth.uid()`).
   - Created authenticated own-row UPDATE policy `Users can update own profile` (`id = auth.uid()`).
   - Anon has NO SELECT or UPDATE privileges on `public.profiles`.
   - Shared drift audit function `public.verify_profiles_policy_drift()` verifies that NO unexpected policies exist on `public.profiles`, rejecting unauthorized `ALL`, `SELECT`, `UPDATE`, `INSERT`, or `DELETE` policies.
2. **Column-Level Update Protection (DB-004)**:
   - Revoked table-level mutating privileges from `anon`, `authenticated`, and `public`.
   - Explicitly granted `UPDATE (full_name, phone, avatar_url, address)` only to `authenticated`.
   - Protected fields (`role`, `email`, `id`, `created_at`, `updated_at`) cannot be modified by clients.
3. **Hardened Signup Trigger (DB-006)**:
   - Replaced `handle_new_user()` with `SECURITY DEFINER` and `SET search_path = public, pg_temp`.
   - Ignores client-supplied `raw_user_meta_data->>'role'` and unconditionally forces `'customer'`.
   - Postcondition verifies existence, schema qualification (`public.handle_new_user()`), `prosecdef = true`, and `search_path=public, pg_temp`.
   - Robust fallback handling for OAuth / missing email (assigns default full name and preserves null email).
4. **Least-Privilege Grants & Table RLS (DB-003)**:
   - Revoked `TRUNCATE`, `REFERENCES`, `TRIGGER` across `profiles`, `destinations`, `trips`, `trip_activities`.
   - `destinations`: public SELECT for anon and authenticated; all mutating privileges revoked. Reconstructed schema: `id text`, `region` check Bắc/Trung/Nam/Tây Nguyên, `weather_cached_temp numeric DEFAULT 26.0`, `is_popular boolean DEFAULT true`.
   - `trips`: faithfully reconstructed with 11 columns matching SRC-DB-001/002, enterprise schema, and `saved_trip_model.dart` (`destination_name text NOT NULL`, without invented `destination_id` or `actual_cost`).
   - `services`: faithfully reconstructed with `title text`, `service_type` checked for `hotel/flight/bus/tour/combo`, with `partner_profiles` dependency.
   - `trip_activities`: exactly 12 columns matching SRC-DB-001; authenticated own-row CRUD enforced under RLS; foreign key cascade integrity verified (child exists before deletion, parent deletion affects exactly 1 row, child cascaded).
5. **Harmonized Negative Controls & Exact Restoration Proof**:
