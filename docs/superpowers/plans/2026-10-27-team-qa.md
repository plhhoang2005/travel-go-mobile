## QA0 — Môi trường và đầu ra

- [ ] Nhận source SHA, APK/build ID + SHA256, debug/profile/release mode, config/environment name, backend function/schema/catalogue version từ owner. Không biết mục nào thì ghi UNKNOWN; nếu không khớp feature đang test thì BLOCKED đúng phần đó.
- [ ] Nhận customer A/B, admin test và target được phép lock/unlock; quyền tạo/sửa/xóa fixture/live requests, AI/quota/email phải rõ. Không dùng user thật/owner admin chính cho ca phá hủy. Credentials chia kênh riêng, không commit collection có bearer token/password/OTP.
- [ ] Ghi thiết bị/Android/app version/mạng/font scale; kiểm còn draft trước cài hoặc đổi config. Không clear data/uninstall/reset để chữa lỗi. Khi ADB chỉ qua Wi-Fi, test mất mạng cần kênh giữ kiểm soát như USB hoặc quy trình thủ công đã thống nhất.
- [ ] Tạo artifacts khi thực thi: `docs/team/qa/TEST_CASES.md`, `API_INVENTORY.md`, `RUN_LOG.md`, `BUGS.md`; evidence trong `docs/team/qa/evidence/` đã che thông tin riêng. Nếu dùng Postman, export collection và environment **template rỗng secrets** tại đây.

Mỗi run gồm case ID, thời gian Asia/Saigon, source/APK/backend/schema/catalogue version, account alias/role, preconditions, steps, expected, actual, PASS/FAIL/BLOCKED/NOT RUN, evidence, bug ID. Không copy token hoặc raw profile payload vào báo cáo.

Chạy trước AUTH/TRIP/MONEY/SAVE/DISC trên build hiện có được bàn giao. C7/AI evidence/web chưa available thì giữ BLOCKED/NOT RUN; thiết kế đích không phải feature sẵn có. Test stale recovery/session dùng cách hợp lệ được giao, không tự lấy token SDK hoặc sửa private storage để giả kết quả.

Từng feature: happy path → invalid input/deny → cancel/retry → network error → account/lifecycle. Khi gặp lỗi quyền/lẫn account/mất dữ liệu, dừng ca liên quan và báo ngay. Không tắt toàn bộ test vì một feature chưa deploy; tiếp tục cases độc lập.

## QA2 — Web API nghĩa là endpoint app thực sự gọi

Không đồng nhất kiểm API với chỉ mở Flutter web, cũng không nhầm Google Search Grounding với toàn bộ Web API. Repo có Supabase Auth/RPC/Edge Functions và backend Java; QA phải lấy request routes/methods/contracts từ **service/index/config thực tế**, không đoán mọi chức năng nằm ở Java `/api/v1` hoặc tự test endpoint map đã ngoài scope.

- [ ] Lập `API_INVENTORY.md`: feature, service source, environment/base URL, method/path/RPC/action, auth role, payload synthetic, response schema + business error/status, owner endpoint, version/deploy evidence.
- [ ] Owner xác nhận inventory trước bộ live mutation; danh sách route có thể thay đổi nên không hardcode từ báo cáo cũ. Dùng token hợp lệ đúng role được cấp; cố ý role sai/token hết hạn theo case được giao, không trích secrets từ người khác.
- [ ] Public catalogue: manifest/bundle đúng version/digest, hidden/all-hidden/empty, malformed/mismatch/lỗi refresh; quan sát state app cùng API result, không chỉ HTTP200.
- [ ] Trip APIs/RPC: create/read/update/delete/retry theo actual contract; owner A không đọc/sửa/delete trip B; stale version và duplicate request giữ đúng semantics. Receipt/body/status phải xác nhận, HTTP200 có business error không phải PASS.
- [ ] Admin: no auth/customer/admin/locked target; action payload/revision/requestId/operation readback đúng; readonly/cancel không gửi mutation. Lock target chỉ được phép, không brute-force hoặc đổi quyền để test qua.
- [ ] AI: schema sai, no auth, quota/timeout/invalid model output giữ draft; late stamp không apply. Lỗi provider mô phỏng trong local tests do coder chạy; live không cố đốt quota để tạo lỗi. Count request thật trong phạm vi cho phép.
- [ ] Ghi request/response đã che token, cookies, email/PII; test dữ liệu synthetic. Không dump toàn profile/SDK session hoặc commit default environment có secrets.

Trên máy Android thật, `10.0.2.2` là cấu hình mặc định cho emulator trong source, không phải địa chỉ laptop dành cho phone. Owner bàn giao URL LAN/staging phù hợp bằng config hiện có; API inventory phải phân biệt Java base URL với Supabase project/functions. Không sửa manifest/firewall/security config chỉ để vượt lỗi kết nối khi chưa xác định nguyên nhân và scope.

## QA3 — Bug và tái kiểm

```text
Bug ID / severity / task sở hữu:
Source SHA / APK hash + mode / backend/schema/catalogue version:

Steps (đủ để người khác làm lại):

Fix PR + exact new SHA:
Retest original case + neighbor regression / result:
```

- [ ] Owner triage và giao đúng coder; QA không tự sửa code hoặc bỏ assertion. Người sửa cung cấp root cause + regression test + bản mới.
- [ ] Tái kiểm nguyên ca lỗi trước, rồi ca gần: ví dụ retry save phải kiểm duplicate + reopen + A/B. Còn lỗi giữ OPEN; hết lỗi nhưng sai build/version thì chưa đóng.
- [ ] Trước merge feature có UI/API, kiểm candidate tích hợp khi khả dụng; nếu chưa có live environment, ghi phạm vi source acceptance riêng, không tuyên bố runtime đạt. Sau merge smoke build mới; trước main/release đủ mandatory acceptance.
- [ ] Lưu kết quả theo run, không ghi đè FAIL lịch sử thành PASS. Gửi evidence đã chốt cho người làm báo cáo.

**Đạt công việc QA:** có coverage scope + reproducible bugs + phiên bản rõ + retest; mọi mandatory case có trạng thái trung thực. Không đặt chỉ tiêu “không tìm thấy lỗi” hoặc số lượng cases thay chất lượng.
